# 몇 대 보내야 탈 수 있을까

**출퇴근 광역버스 정류장별 빈자리 예측**

출퇴근 시간에 광역버스가 내 정류장에 올 때 빈자리가 있을지 예측하고, 만석이면 몇 번째 버스부터 탈 수 있는지 알려 주는 프로젝트입니다.

> 대학생 팀의 비영리 연구 프로젝트이며, 국토교통 데이터 활용 경진대회 출품을 준비하고 있습니다.

---

## 왜 필요한가

고속도로를 달리는 수도권 광역버스(경기 직행좌석·M버스, 서울 광역버스)는 입석이 금지되어 있습니다. 그래서 출근 시간에는 기점 근처에서 자리가 다 차고, 중간 정류장 이용자는 만석 버스를 여러 대 보낸 뒤에야 타는 일이 흔합니다.

카카오맵에서 운행별 과거 잔여좌석은 볼 수 있지만, **오늘 상황을 반영해 몇 번째 버스부터 탈 수 있는지 알려 주는 예측도**, **정류장별로 얼마나 더 기다리는지 재는 지표도 없습니다.**

## 무엇을 만드나

| 결과물 | 대상 | 내용 |
| --- | --- | --- |
| 빈자리 예측 웹 | 통근자 | 정류장을 고르면 다음 버스 5대의 빈자리 확률, 몇 번째 버스부터 탈 수 있는지, 예상 대기 시간 |
| 격차 대시보드 | 지자체 | 정류장별로 탑승까지 보내는 만석 버스 수와 늘어난 대기 시간 |
| 분석 보고서 | 공모전·정책 | 과거 기록을 그대로 쓰는 방식(베이스라인) 대비 예측 성능, 증차·중간 출발 배치 제안 |

## 현재 상태 (2026-11-12)

- **데이터 수집기 가동 중** (2026-11-10 퇴근 시간부터). 공공 API는 지금 이 순간의 값만 주기 때문에, 수집 기간이 곧 학습 데이터 양입니다.
- 수집 대상: **8개 노선** (2026-11-12부터. 11/10~11/11에는 7770·M4101·M5107·9401 4개)

  | 노선 | 구분 | 운행 구간 | 수집원 |
  | --- | --- | --- | --- |
  | 7770 | 경기 직행좌석 | 수원역 ↔ 사당역 | 경기 버스위치(GBIS), TAGO(위치 백업) |
  | M4101 | M버스 | 용인 ↔ 숭례문 | 경기 버스위치(GBIS), TAGO(위치 백업) |
  | M5107 | M버스 | 경희대 ↔ 서울역 | 경기 버스위치(GBIS), TAGO(위치 백업) |
  | 9401 | 서울 광역 | 분당 구미동 ↔ 서울역 | 서울 버스위치 |
  | 1000 | 경기 직행좌석 | 고양 대화동 ↔ 숭례문 | 경기 버스위치(GBIS) |
  | 5005 | 경기 직행좌석 | 용인 남동차고지 ↔ 서울역 | 경기 버스위치(GBIS) |
  | 1500-2 | 경기 직행좌석 | 용인 에버랜드 ↔ 사당역 | 경기 버스위치(GBIS) |
  | 8002 | 경기 직행좌석 | 남양주 대성리 ↔ 잠실광역환승센터 | 경기 버스위치(GBIS) |

  호출 간격: 평일 출근 05:30 ~ 09:59, 퇴근 17:00 ~ 21:59에 **1분 간격**(TAGO는 출근 06:00부터). 주말·공휴일은 08:00 ~ 21:59에 3~5분 간격입니다.
  기상청 초단기실황(노선 주변 격자 10곳)도 매시간 함께 수집합니다.
- 경기·서울 버스위치 API는 운영계정(하루 10,000건)을 받아, 2026-11-12에 대상 노선을 4개에서 8개로 늘리고 경기 노선의 첨두 간격을 2분에서 1분으로 줄였습니다.
- 새 노선(1000·5005·1500-2·8002)은 잔여좌석이 있는 경기 버스위치(GBIS)로만 수집합니다. TAGO는 잔여좌석을 주지 않아 기존 3개 노선의 위치 백업으로만 씁니다.

각 데이터의 이용 조건은 공공데이터포털의 이용허락범위를 따릅니다.

## 동작 구조

```
 공공 API ──(첨두 1분 간격 호출)  ──▶ collect.py ──▶ data/raw/<작업>/<날짜>.jsonl
                                        │                (지난 날짜는 자동 압축)
                                        ├─ 하루 호출 수 장부: 한도의 95%에서 멈춤
                                        └─ 수집 공백 기록: data/logs/gaps.csv

 data/raw ──▶ daily_report.py ──▶ 하루 점검표 (호출 성공률, 정류장별 만석 도착·출발 비율,
                                              연속 만석 대수, 차량 정원 추정)

 data/raw ──▶ 운행 1회 × 정류장 표 ──┬──▶ 정류장 지표 ──▶ 격차 대시보드
             (개발 중)               └──▶ 빈자리 확률 모델(LightGBM) ──▶ 탑승 순번 계산 ──▶ 예측 웹
```

## 저장소 구성

| 파일 | 하는 일 |
| --- | --- |
| `collect.py` | 시간표대로 API를 호출해 원본 저장 (PC에 켜 두는 수집기) |
| `daily_report.py` | 하루 수집 결과 점검표 |
| `check_apis.py` | 신청한 API를 한 번씩 호출해 점검표 작성, 노선 ID 찾기 |
| `selftest.py` | 인터넷·키 없이 가짜 응답으로 전체 흐름 확인 |
| `common.py`, `endpoints.py` | 공통 함수, API 주소 모음 |
| `config.yaml` | 노선, 호출 간격, 하루 호출 한도 |
| `.env.example` | 인증키 입력 양식 (실제 키는 `.env`에 넣고 저장소에는 올리지 않음) |
| `run_collect.bat`, `run_collect.sh` | 수집기가 꺼지면 자동으로 다시 켜는 실행 파일 |
| `docs/SETUP.md` | 설치, 인증키 넣기, 수집 시작, 매일 점검 방법 |

**처음 설치한다면 [docs/SETUP.md](docs/SETUP.md)를 보세요.**

인증키(`.env`)와 수집 원본(`data/`)은 저장소에 올리지 않습니다. 원본 파일에도 인증키는 남지 않습니다.
