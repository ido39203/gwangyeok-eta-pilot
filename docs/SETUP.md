# 설치와 운영 안내 — API 점검 스크립트와 수집기

프로젝트 소개는 [README](../README.md)에 있습니다. 이 문서는 수집기를 설치하고 매일 운영하는 방법입니다.
명령은 모두 **저장소 맨 위 폴더**(`collect.py`가 있는 곳)에서 실행합니다.

처음에는 수도권 광역버스 위치와 도로·기상 데이터를 1~2주 동안 모아 보는 파일럿용으로 만들었습니다(정류장 통과 시각을 제대로 잡을 수 있는지, 어느 API를 주 수집원으로 쓸지 확인). 2026-11-10부터는 이 코드로 본 수집을 하고 있습니다.

| 파일 | 하는 일 | 언제 |
| --- | --- | --- |
| `selftest.py` | 인터넷·키 없이 가짜 응답으로 전체 흐름 확인 | 설치 직후 1번 |
| `check_apis.py` | 신청한 API를 한 번씩 호출해 점검표 작성, 노선 ID 찾기 | 수집 시작 전 1번 (키를 바꿨을 때도) |
| `collect.py` | 시간표대로 계속 호출해 원본 저장 | PC에 켜 두기 |
| `daily_report.py` | 하루 수집 결과 점검표 | 매일 1번 |
| `config.yaml` | 노선, 호출 간격, 도로·기상 설정 | 필요할 때 수정 |
| `.env` | 인증키 3종 (직접 만듦, 절대 공유 금지) | 처음 1번 |

---

## 1. 설치 (처음 한 번)

파이썬 3.10 이상이 필요합니다. 이 폴더에서 명령 프롬프트(또는 터미널)를 열고:

```bash
python -m venv .venv
.venv\Scripts\activate          # 맥·리눅스는 source .venv/bin/activate
pip install -r requirements.txt
python selftest.py
```

마지막 줄에 `전체 통과`가 나오면 설치는 정상입니다.

## 2. 인증키 넣기

1. `.env.example` 파일을 복사해서 이름을 `.env`로 바꿉니다.
2. 세 줄에 키를 붙여 넣습니다. 따옴표는 쓰지 않습니다.
   - `DATA_GO_KR_KEY`: 공공데이터포털 마이페이지의 **Decoding 키** (코드가 알아서 인코딩합니다)
   - `EX_KEY`: 고속도로 공공데이터 포털 인증키
   - `SEOUL_KEY`: 서울 열린데이터광장 인증키
3. `.env`는 깃허브나 메신저에 올리지 마세요. `.gitignore`에 이미 들어 있습니다.

## 3. config.yaml에서 꼭 채울 두 곳

- `road_ex.realtime_url`: 도로공사 apiId=0405 페이지의 **요청 URL**을 붙여 넣습니다 (`?key=` 앞까지). 비워 두면 도로공사 수집을 건너뜁니다.
- `seoul_traffic.test_link_id`: 서울 도로 소통을 점검할 링크 ID 1개입니다. 아직 모르면 비워 두세요. 비워 두면 키가 유효한지만 확인합니다.
  - 서비스명(`service`)은 기본값이 `TrafficInfo`입니다. 열린데이터광장 OA-13291 페이지 Open API 탭의 샘플 URL과 다르면 그걸로 고칩니다.

## 4. API 점검

```bash
python check_apis.py
```

화면에 점검표가 나오고, `data/check_results/api_check_날짜_시각.csv`(엑셀로 열림)와 API별 응답 예시(`samples/*.json`)가 저장됩니다.

| 결과 | 뜻 | 할 일 |
| --- | --- | --- |
| 성공 | 응답이 오고 데이터도 1건 이상 | 없음 |
| 확인 필요(0건) | 응답은 정상인데 데이터가 0건 | 버스 위치는 운행 시간 밖이면 0건이 정상. 첨두 시간에 다시 실행 |
| 실패(응답 형식) | JSON이 아닌 오류 응답 | 메시지 확인 (아래 표) |
| 실패(HTTP)·실패(연결) | 주소 오류나 인터넷 문제 | 메시지와 함께 알려 주기 |
| 건너뜀 | 키나 설정이 비어 있음 | 비고 칸 안내대로 채우기 |

자주 나오는 메시지:

| 메시지 | 원인 | 해결 |
| --- | --- | --- |
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 키가 아직 반영 안 됨, 또는 Encoding 키를 넣음 | 신청 후 1~2시간 기다리기, Decoding 키로 바꾸기 |
| `SERVICE_ACCESS_DENIED_ERROR` | 활용 승인이 안 된 API | 마이페이지에서 승인 상태 확인 (ASOS는 기관 전용이라 이럴 수 있음) |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 오늘 호출 한도 초과 | 내일 다시. 운영계정 증액 신청 |

점검이 끝나면 찾은 노선 ID가 `data/state/resolved_routes.json`에 저장되고, 수집기는 이 값을 씁니다.
같은 번호 노선이 여러 개 나오면(비고 칸에 안내가 뜸) `config.yaml`의 `route_id`에 원하는 ID를 직접 적어 고정하세요.
2026-11-12에 추가한 4개 노선(1000·5005·1500-2·8002)은 `config.yaml`에 `route_id`를 고정해 두었습니다.
노선 정보·경유 정류소 목록은 `data/ref/`에 저장됩니다. 나중에 급행 구간(O_last·D_first)을 정의할 때 씁니다.

## 5. 수집 시작

```bash
python collect.py --once     # 지금 시각 기준으로 한 바퀴만. 오류 없는지 확인
python collect.py            # 계속 수집. 멈출 때는 Ctrl+C
```

PC에 켜 두는 방법(윈도우):

1. `run_collect.bat`을 더블클릭하면 수집기가 꺼져도 30초 뒤 자동으로 다시 켜집니다.
2. 로그온할 때 자동으로 켜려면: 작업 스케줄러 → 기본 작업 만들기 → 트리거 "로그온할 때" → 동작 "프로그램 시작" → `run_collect.bat` 선택.
3. 설정 → 시스템 → 전원에서 **절전 모드를 "안 함"**으로 바꿉니다. 노트북이면 전원을 연결하고, 덮개를 닫을 때 동작도 "아무 것도 안 함"으로 바꿉니다.
4. 윈도우 업데이트에서 **업데이트 일시 중지**로 파일럿 기간 동안 자동 재시작을 미룹니다.
5. 설정 → 시간 및 언어에서 **자동으로 시간 설정**을 켭니다.
6. 이 폴더를 OneDrive·구글 드라이브 같은 **동기화 폴더 밖**에 둡니다. 동기화 중 파일이 잠기면 저장이 실패할 수 있습니다.

PC가 꺼지거나 절전에 들어갔던 시간은 `data/logs/gaps.csv`에 자동으로 기록됩니다. 숨기지 않고 남겨 두었다가 나중에 그 시간대는 학습 비중을 낮춥니다.

## 6. 매일 점검

```bash
python daily_report.py                 # 오늘
python daily_report.py --date 2026-10-06
```

`data/reports/daily_날짜.md`로도 저장됩니다. 이렇게 판단하세요.

| 항목 | 기준 | 기준에 못 미치면 |
| --- | --- | --- |
| HTTP 200 비율 | 95% 이상 | 실패 예시의 메시지 확인 |
| 2칸 이상 건너뜀 비율 | 낮을수록 좋음. 20%가 넘으면 통과 시각을 많이 놓치는 것 | 그 출처의 `every_sec`를 줄이기 (한도 안에서) |
| GBIS와 TAGO 차량 일치율 | 꾸준히 90% 이상 | TAGO를 경기 노선 주 수집원으로 쓰지 않기 |
| 도로공사 stdHour 바뀌는 간격 | 5분이면 지금 설정 그대로 | `road_ex.every_sec`를 그 간격에 맞추기 |
| 도로공사 노선번호 목록 | 이틀 동안 전국 전체가 저장됨 | 사흘째부터 쓸 `keep_route_nos`를 목록 보고 채우기 (안 채우면 전체를 계속 저장해 용량이 큼) |
| 수집 공백 | 없을수록 좋음 | PC 설정(5절) 다시 확인 |

토·일·공휴일 점검표는 빈자리(8절)를 출근/퇴근 대신 방향별로 보여 줍니다. 서울행은 평일 출근, 귀가는 평일 퇴근과 같은 승차 정류장이고, 하루 전체(06:00 ~ 21:59) 요약 뒤에 2시간 구간 표가 붙습니다. 공휴일은 수집기가 받아 둔 `data/state/holidays_<연도>.json`으로 판단합니다.

## 7. 저장 구조

```
data/
  raw/<작업>/<날짜>.jsonl      한 줄 = 호출 1회 (지난 날짜는 .jsonl.gz로 자동 압축)
      bus_gbis, bus_tago, bus_seoul, road_ex, weather, seoul_link
  state/resolved_routes.json   찾은 노선 ID
  state/quota_<날짜>.json       API별 오늘 호출 수 (점검·수집 합계)
  state/holidays_<연도>.json    공휴일 목록 (공휴일은 주말 시간표를 씀)
  logs/collect.log             실행 기록
  logs/gaps.csv                수집 공백
  ref/                         노선 정보, 경유 정류소 목록, 도로공사 노선 목록
  check_results/               API 점검표와 응답 예시
  reports/                     하루 점검표
```

원본 한 줄에는 호출 시각(`ts`), 주소(키 제외), HTTP 상태, 결과 코드, 항목 수(`n`), 그리고 받은 항목 원본(`items`)이 들어 있습니다.
**인증키는 원본 파일에 남지 않습니다.**
`.jsonl` 파일은 엑셀로 열어 저장하지 마세요(인코딩이 깨질 수 있음). 메모장이나 파이썬으로 엽니다.

## 8. 하루 예상 호출 수 (2026-11-14 기준)

대상 노선은 8개입니다: 경기 7개(7770·M4101·M5107·1000·5005·1500-2·8002), 서울 1개(9401).

| 묶음 | 평일 | 주말·공휴일 | 하루 한도 |
| --- | --- | --- | --- |
| 경기 버스위치 (7개 노선, 평일 첨두 1분·주말 2분) | 3,990 | 3,360 | 10,000 (운영계정) |
| TAGO 버스위치 (7770·M4101·M5107, 첨두 1분 + 그 외 5분) | 1,980 | 1,710 | 10,000 |
| 서울 버스위치 (9401, 평일 첨두 1분·주말 2분) | 570 | 480 | 10,000 (운영계정) |
| 기상청 초단기실황 (격자 10곳, 매시) | 최대 480 | 최대 480 | 10,000 |
| 도로공사 0405 (5분, 현재 미수집) | 288 | 288 | 포털에서 확인 |

- 경기·서울 버스위치의 평일 첨두는 출근 05:30 ~ 09:59, 퇴근 17:00 ~ 21:59로 모두 9시간 30분입니다. 1분 간격이면 노선 하나에 하루 570회를 호출합니다.
- 주말·공휴일은 06:00 ~ 21:59에 경기·서울 모두 2분 간격입니다(노선 하나에 하루 480회). 출퇴근 구분 없이 하루 전체를 같은 간격으로 받습니다. TAGO는 출근 06:00부터 1분 간격이고, 그 밖의 시간에도 5분(주말 2분) 간격으로 위치를 받습니다.
- 기상은 격자마다 한 시간에 한 번 부르고, 그 시각 자료가 아직 없으면 한 시간 전 자료를 한 번 더 부르므로 최대 2회입니다.
- 한도의 95%(9,500건)에 닿으면 그날은 그 API를 더 호출하지 않습니다(`config.yaml`의 `quota`). 지금 설정이면 경기는 노선을 9개, 서울은 15개 더 늘려도 이 안에 들어옵니다.
- 한도가 바뀌면 `quota.limits` 숫자만 바꾸고 수집기를 다시 켜면 됩니다.

## 9. 실제 키로 확인한 것과 아직인 것

확인함(2026-11-10부터 수집 중):
- 경기(GBIS) v2 버스위치, TAGO 버스위치, 서울 버스위치(`http://ws.bus.go.kr/api/rest`), 기상청 초단기실황.
- 경기·서울 버스위치 운영계정 한도(10,000건) 반영: 2026-11-12 경기 버스위치 하루 1,680건이 모두 성공(1,000건 넘은 뒤도 정상).
- TAGO 버스위치 응답에는 잔여좌석이 없어 위치 백업으로만 씁니다. 서울은 만석이 이어지면 잔여좌석 값 대신 `isFullFlag=1`이 붙으므로 만석으로 처리합니다.

아직(필요해지면 확인):
- 서울 도로 소통의 서비스명(`TrafficInfo`)과 응답 필드명.
- 도로공사 0405는 주소를 직접 넣어야 합니다(`road_ex.realtime_url`).
